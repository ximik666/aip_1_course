Расширенная программа курса Алгоритмизация и программирование

Учебный комплект для первого курса. Проект программы рассчитан на обучение с нуля на Python в течение двух семестров. Это предлагаемая модель нагрузки, а не утверждённая рабочая программа вуза. Даты и нормативные требования образовательной организации следует внести при внедрении.

Нагрузка и организация

В каждом семестре 16 недель, 32 академических часа лекций, 32 часа практик и 44 часа самостоятельной работы, всего 108 часов. За год 216 часов: 64 лекционных, 64 практических, 88 самостоятельных. Самостоятельная работа каждого семестра: 24 часа подготовки и закрепления тем, 20 часов семестрового проекта. Академический час равен 45 минутам. Исследовательские задания являются выборным углублением в пределах самостоятельной работы, а не обязательным дополнением ко всем базовым заданиям.

Каждая неделя содержит одну лекцию и одну практику. Контрольные работы занимают по 45 минут практик недель 8 и 14, оставшиеся 45 минут предназначены для обратной связи и разбора. На этих неделях прикладную задачу соответствующей практики разрешается завершить самостоятельно вместо исследовательской. Практика недели 16 предназначена для защиты. При группе более 12 человек защиту распределить между неделями 15 и 16, часть практических обсуждений провести письменно. Не планировать 25 индивидуальных защит по 10 минут в одну пару.

Контракт задачи

Алгоритм задаёт однозначную последовательность действий. Начинаем с контракта: какие данные разрешены, какой результат требуется и что считать ошибкой. Для суммы покупок входом служат цены в целых копейках, выходом — неотрицательное целое число. Если цена отрицательна, это уже другая постановка: возврат товара или ошибка ввода. Программа не должна молча выбирать трактовку за автора задания.

Исполнитель и состояние

Исполнитель выполняет команды, меняющие состояние. Состояние можно записать таблицей значений переменных после каждого шага. Сначала полезно решить пример вручную, затем записать псевдокод и только потом перевести его на Python. Это отделяет ошибку замысла от ошибки синтаксиса. Один успешный пример показывает возможность решения, но ещё не доказывает правильность для всех входов.

Свойства решения

Для учебных задач требуем завершение на каждом допустимом входе и соответствие контракту. Конечность входа сама по себе не гарантирует завершение программы: цикл может не менять управляющую переменную. Проверяем обычный случай, минимальный вход и границу условия. Для алгоритма покупки упаковок отдельно рассматриваем точное деление и наличие остатка.

От текста к выполнению

Исходный файл содержит текст программы. Интерпретатор Python проверяет его синтаксис и выполняет инструкции. В интерактивном режиме выражения удобно исследовать по одному, а файл позволяет повторить весь опыт. В CPython исходный код обычно компилируется в байткод и выполняется виртуальной машиной. Поэтому деление языков на исключительно компилируемые и исключительно интерпретируемые слишком грубо.

Типы и операции

int хранит целые числа, float — приближённые вещественные. Оператор / выполняет обычное деление, // — деление с округлением вниз, % — остаток. Для положительного делителя b выполняется a=(a//b)*b+a%b. В Python -7//3 равно -3, а не -2. Скобки явно фиксируют требуемый порядок вычислений.

Табличный формат

Модель стоимости

Время на конкретном компьютере зависит от оборудования, реализации и входных данных. Асимптотическая оценка описывает рост затрат при увеличении n. O(n) — верхняя оценка линейного порядка в выбранной модели, а не точное число секунд. Указываем, что считаем элементарной операцией и какой параметр обозначает n.

Последовательные и вложенные действия

Два последовательных прохода по n элементам дают линейный рост: n+n=2n. Два вложенных полных прохода дают n² пар. Если внутренний цикл начинается с i+1, число пар равно n(n-1)/2 и порядок остаётся квадратичным. Слово «вложенный» само по себе недостаточно: внутренний диапазон может быть константным.

Память и случаи

Дополнительная память не всегда равна размеру входа. Сумма с одним накопителем требует O(1) дополнительной памяти, копирование списка — O(n). Для поиска различаем лучший случай, когда элемент первый, и худший, когда его нет. Оценку среднего случая можно давать только с предположением о распределении входов.

Линейная проверка

Линейный поиск проверяет элементы по порядку и подходит для несортированных данных. Если требуется первый индекс, возвращаем результат сразу при первом совпадении. Отсутствие обозначаем -1. Худший случай требует n сравнений, дополнительная память постоянна.

Половинное сужение

Бинарный поиск требует упорядоченности и отбрасывает половину оставшегося диапазона после сравнения со средним. В варианте lower_bound поддерживаем полуинтервал [lo,hi). Слева от lo находятся элементы меньше цели, начиная с hi — элементы не меньше цели. В конце lo==hi указывает позицию вставки.

Стоимость подготовки

Поиск в готовом отсортированном списке занимает O(log n) сравнений. Если ради одного запроса сначала сортировать данные, нужно учитывать стоимость сортировки. Кроме того, индексы в отсортированном списке уже не совпадают с исходными. Контракт должен уточнять, какой индекс требуется.

def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:

        else:
            hi = mid
    return lo

Сортировка вставками сохраняет отсортированный префикс. Очередной элемент временно сохраняется, большие элементы сдвигаются вправо, затем значение вставляется на свободное место. На уже отсортированном входе достаточно линейного числа сравнений, в худшем случае число сдвигов квадратично.

Стабильность

Стабильная сортировка сохраняет относительный порядок записей с одинаковым ключом. Во вставках условие строго больше сохраняет порядок равных значений. Замена на больше или равно может нарушить стабильность. Для чисел это незаметно, поэтому проверять свойство надо на записях с метками.

        x, j = a[i], i - 1
        while j >= 0 and a[j] > x:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
    return a

Абстракция стека

Стек выдаёт последним добавленный элемент первым. list.append и list.pop с конца подходят для этой модели. Важен не только контейнер, но и разрешённые операции. Стек вызовов, отмена действий и незавершённые скобки используют одинаковый порядок вложенности.

Сопоставление скобок

Открывающую скобку кладём в стек. Для закрывающей сначала проверяем, что стек не пуст, затем сравниваем с последней открывающей нужного типа. Несовпадение означает ошибку независимо от оставшегося текста. В конце стек должен оказаться пустым. Простого равенства количества открывающих и закрывающих недостаточно.

Нужно заранее решить, что делать с буквами и пробелами. В нашем примере они игнорируются. Поэтому алгоритм проверяет скобочную структуру текста, но не синтаксис Python: кавычки и комментарии не распознаются. Для полноценного языка нужен анализатор с другими правилами.

    stack = []
    pairs = {")": "(", "]": "[", "}": "{"}
    for c in text:
        if c in "([{":
            stack.append(c)
        elif c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
    return not stack

Транспонирование

Транспонирование меняет роли строки и столбца: элемент i,j становится j,i. Матрица 2×3 превращается в 3×2. Двойное транспонирование возвращает исходные данные, что даёт полезное свойство для тестирования. Новый результат не должен разделять изменяемые строки с исходной матрицей.

Умножение

Для A размера m×n и B размера n×p произведение имеет размер m×p. Его элемент i,j равен сумме A[i][k]*B[k][j] по k. Это отличается от поэлементного умножения. Стандартная тройная реализация требует O(mnp) арифметических операций. В общем случае AB и BA различаются, а одно из произведений может быть вообще не определено.

Модель графа

Граф состоит из вершин и рёбер. Словарь списков соседей хранит только существующие связи и удобен для разреженных графов. В неориентированном графе каждое ребро записываем в обе стороны. Изолированную вершину тоже включаем с пустым списком, иначе она исчезает из модели.

Слои обхода

Поиск в ширину использует очередь. Сначала обрабатываются вершины расстояния 0, затем 1, затем 2 и далее. В невзвешенном графе первое обнаружение вершины даёт кратчайшее расстояние по числу рёбер. Вершину отмечаем посещённой при добавлении в очередь, чтобы разные соседи не добавили её многократно.

Восстановление пути

Сохраняем родителя, от которого впервые пришли в вершину. После достижения цели идём по родителям назад и разворачиваем список. При недостижимости возвращаем None, а для старта, совпадающего с целью, путь состоит из одной вершины. BFS не решает общую задачу кратчайшего пути с разными весами рёбер.

from collections import deque
graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
distance = {"A": 0}
q = deque(["A"])
while q:
    v = q.popleft()

        if u not in distance:
            distance[u] = distance[v] + 1
            q.append(u)
assert distance["D"] == 2

Экземпляр и состояние

Класс задаёт устройство объектов, экземпляр хранит конкретные данные. self передаёт методам текущий объект. Два экземпляра должны иметь независимое состояние, если совместное хранение не задумано специально. Изменяемый список на уровне класса разделяется всеми экземплярами и часто становится ошибкой новичка.

Инвариант объекта

Инвариант — условие, которое должно сохраняться после любой публичной операции. Для остатка товара это целое неотрицательное количество. Конструктор проверяет начальное состояние, метод выдачи отклоняет отрицательное число и нехватку остатка. Сначала все проверки, затем изменение: ошибка не должна оставлять объект наполовину обновлённым.

Приложение может содержать каталог, который содержит записи. Это композиция объектов. Протокол перебора

Итерируемый объект позволяет получить итератор. Итератор выдаёт следующий элемент через next и сообщает о завершении через StopIteration. Список можно обходить многократно, создавая новый итератор. Сам исчерпанный итератор обычно повторно данных не выдаёт. Это различие важно при повторных вычислениях.

Приостановленное вычисление

Функция с yield возвращает генератор. При очередном запросе она выполняется до yield и сохраняет локальное состояние. Значения можно обрабатывать по одному без списка всех результатов. Но если потребитель вызвал list(generator), он сам материализовал все элементы и потерял преимущество по памяти.

Функции как значения

Функцию можно передать другой функции, например key в sorted. Для простой операции подходит lambda, для сложной логики лучше именованная функция. Читаемость важнее минимального числа строк. Генераторное выражение внутри sum позволяет вычислить сумму преобразованных элементов без промежуточного списка.

Повторяющиеся подзадачи

Если один и тот же результат требуется многократно, его можно вычислить один раз и сохранить. Для числа способов подняться по лестнице шагами 1 или 2 последний шаг приходит либо с предыдущей, либо с предпредыдущей ступени. Эти варианты не пересекаются, поэтому ways[n]=ways[n-1]+ways[n-2].

Состояние и база

Состояние должно содержать достаточно информации для продолжения решения. Здесь достаточно номера ступени. Для нулевой ступени существует один способ: не делать шагов, поэтому ways[0]=1. Для первой ступени способ тоже один. Неверная база меняет все последующие значения даже при правильном переходе.

Порядок и память

Таблицу заполняем от меньших индексов к большим, чтобы зависимости были готовы. Если нужен только итог, достаточно двух предыдущих значений и O(1) ячеек вместо O(n). Эта оценка считает арифметическую операцию постоянной: фактическая стоимость больших целых растёт с числом разрядов. Сохранение всей таблицы полезно для объяснения и восстановления решения.

def stair_ways(n):
    if type(n) is not int or n < 0:
        raise ValueError("нужно целое n >= 0")
    ways = [1] * (n + 1)
    for i in range(2, n + 1):
        ways[i] = ways[i-1] + ways[i-2]
    return ways[n]

Семестровая работа 1 Комплексный калькулятор

Назначение

Разработать модуль операций над комплексными числами и консольный интерфейс. Обязательное ядро реализуется самостоятельно без встроенного complex и внешних библиотек. В преподавательском эталонном тесте complex допустим как независимый способ проверки.

Обязательный контракт

Модуль называется semestr_task.py. Функции summa(values), raznost(values), multi(values), divide(values) принимают ровно list длины 4: [a,b,c,d] для чисел a+bi и c+di. Элементы имеют точный тип int или float, bool и числовые строки запрещены. Значения конечны, модуль каждого не больше 10^6. Деление дополнительно требует c²+d²≥10^-12; меньший знаменатель считается выходом из учебной области допустимых данных. Это явное ограничение предотвращает непредсказуемый рост ошибки около нуля, а не математическое определение нулевого числа.

Семестровая работа 2 Матричная библиотека

Назначение

Разработать модуль matrix_ops.py и консольный запуск операции над матрицами из JSON. Сохраняется математическая направленность исходного курса, но неоднозначное «деление матриц» исключено. Все операции реализуются самостоятельно на списках и стандартной библиотеке. NumPy и готовые реализации линейной алгебры в студенческом ядре не используются.

Вход и ошибки

Матрица — точный тип list, от 1 до 20 строк, каждая строка — list одинаковой длины от 1 до 20. Числа имеют точный тип int или float, конечны, |x|≤1000. bool запрещён. Пустые и рваные матрицы недопустимы. При неверном входе или несовместимой форме функция поднимает ValueError. Функции сохраняют исходные списки и возвращают новые результаты. Печать и файловый ввод находятся вне ядра.

Восемь обязательных операций

Функция Контракт
add(A,B) Поэлементная сумма, формы совпадают
subtract(A,B) Поэлементная разность A-B, формы совпадают
matmul(A,B) Матричное произведение, число столбцов A равно числу строк B
transpose(A) Матрица n×m для входа m×n
determinant(A) Только квадратная, метод исключения с выбором опоры, знак обменов учтён
rank(A) Количество опор после исключения, допускается прямоугольная форма
norm1(A) Максимум по столбцам суммы модулей элементов
count_nonzero(A) Число элементов, точно не равных 0; здесь eps не применяется

Для determinant и rank используется абсолютный порог eps=1e-9: элемент с модулем ≤eps считается нулевым. Опору выбирают по максимальному модулю в доступной части столбца. Определитель после исключения равен произведению ненормированных опор с поправкой на обмены. Если опора не найдена, determinant возвращает 0.0. Для rank такой столбец пропускается, поиск продолжается в следующем. Оценка ранга является численной, зависит от порога и не заменяет точную символьную алгебру. На защите требуется показать пример чувствительности к масштабу.

В проверках результатов использовать rel_tol=1e-7 и abs_tol=1e-7. Для ранга ожидается точное целое при указанном eps. Базовые тесты используют хорошо обусловленные малые целочисленные матрицы. Пограничные вещественные случаи обсуждаются отдельно и не оцениваются по неоговорённому эталону.

Интерфейс и данные

Запуск: python3 main.py input.json output.json. Вход содержит operation и A, а для бинарной операции также B. Пример: {"operation":"matmul","A":[[1,2]],"B":[[3],[4]]}. Выход: {"result":[[11]]}. Неизвестная операция или неверные данные дают {"error":"понятное сообщение"} и ненулевой код завершения. Входной и выходной путь должны различаться. Отсутствующий файл и неверный JSON обрабатываются явно. Успешный результат записывается в UTF-8 JSON.

Приёмочные примеры

  • transpose([[1,2,3],[4,5,6]]) → [[1,4],[2,5],[3,6]].
  • add([[1,2]],[[3,4]]) → [[4,6]]. subtract → [[-2,-2]].
  • matmul([[1,2]],[[3],[4]]) → [[11]].
  • determinant([[0,2],[3,4]]) → -6.0.
  • determinant([[1,2],[2,4]]) → 0.0, rank той же матрицы → 1.
  • rank([[0,0],[0,0]]) → 0.
  • norm1([[-1,2],[3,-4]]) → 6; count_nonzero([[0,2],[3,0]]) → 2.
  • [], [[]], [[1],[2,3]], [[True]], [[NaN]], несовместимые размеры → ValueError.

Дополнительные свойства: T(T(A))=A, A+0=A, A*I=A, сумма входов не меняет ни один операнд. Не проверять коммутативность матричного умножения как общее свойство.

Индивидуальные варианты

  1. Протокол Гаусса. Для rank и determinant сохранять список обменов и вычитаний строк. Каждая запись содержит индексы и коэффициент. Проверить воспроизведение протокола на копии исходной матрицы.
  2. Система уравнений. Реализовать solve(A,b) для квадратной невырожденной A. Для вырожденной поднять ValueError, не пытаться классифицировать все решения. Проверить остаток A*x-b с допуском и пример x=[1,2].
  3. Степень матрицы. Реализовать power(A,k), k — целое 0..20, A квадратная. k=0 возвращает единичную. Сравнить последовательное и быстрое возведение по числу умножений.
  4. Анализ таблицы. Дополнительно вычислять суммы строк, суммы столбцов, след квадратной матрицы и симметричность с допуском. На прямоугольной матрице след и симметричность отклонять. Проверить 1×1 и отрицательные элементы.
  5. Пакет операций. Вход — список независимых запросов. Вернуть результаты в том же порядке с индексами, ошибка одного запроса не прекращает пакет. Проверить смешанный набор успешных и ошибочных запросов.
  6. Численный эксперимент. На наборах матриц размеров 2,4,8,16 сравнить время matmul и исключения, 5 повторов на размер. Генерация вне измерения, seed фиксирован. Представить таблицу, график и ограничения вывода. Отдельно показать влияние eps на вычисленный ранг.
