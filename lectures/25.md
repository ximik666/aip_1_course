## Представление

Матрицу представляем непустым списком непустых строк одинаковой длины. Вход [[1,2],[3]] не является прямоугольной матрицей. Размер m×n означает m строк и n столбцов. Проверку формы выполняем один раз на границе операции, а не обнаруживаем проблему случайным IndexError в середине вычислений.

## Транспонирование

Транспонирование меняет роли строки и столбца: элемент i,j становится j,i. Матрица 2×3 превращается в 3×2. Двойное транспонирование возвращает исходные данные, что даёт полезное свойство для тестирования. Новый результат не должен разделять изменяемые строки с исходной матрицей.

## Умножение

Для A размера m×n и B размера n×p произведение имеет размер m×p. Его элемент i,j равен сумме A[i][k]*B[k][j] по k. Это отличается от поэлементного умножения. Стандартная тройная реализация требует O(mnp) арифметических операций. В общем случае AB и BA различаются, а одно из произведений может быть вообще не определено.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/25.py` из корня комплекта.

```python
A = [[1, 2, 3], [4, 5, 6]]
B = [[1, 0], [0, 1], [1, 1]]
C = [[sum(A[i][k] * B[k][j] for k in range(3))
      for j in range(2)] for i in range(2)]
assert C == [[4, 5], [10, 11]]
T = [list(col) for col in zip(*A)]
assert T == [[1, 4], [2, 5], [3, 6]]
```

C[0][0]=1*1+2*0+3*1=4. C[0][1]=1*0+2*1+3*1=5. В примере форма заранее известна, в проекте требуется валидатор.

## Типичная ошибка

zip обрезает по самой короткой строке. Нельзя использовать его как замену проверки прямоугольности.
