## Ресурс и кодировка

with закрывает файл при выходе из блока, включая выход из-за исключения. Для русскоязычных данных явно задаём encoding="utf-8". Режим w очищает существующее содержимое, a добавляет в конец. Перед записью нужно понимать, является файл исходными данными или результатом вычисления.

## Табличный формат

CSV хранит строки и столбцы, но не хранит тип Python каждого значения. После чтения цена остаётся строкой и требует преобразования. Самостоятельное разделение строки по запятой ломается, если разделитель входит в кавычки поля. Поэтому используем csv.DictReader и заранее фиксируем имена столбцов.

## Структурированный формат

JSON представляет списки, объекты, числа, строки, логические значения и null. json.loads разбирает синтаксис, но не доказывает соответствие предметной схеме. После чтения списка расходов всё равно проверяем обязательные поля, типы и уникальность идентификаторов. Нельзя загружать недоверенные данные через eval.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/12.py` из корня комплекта.

```python
import csv
import io
import json
rows = list(csv.DictReader(io.StringIO("name,cents\nчай,120\n")))
assert int(rows[0]["cents"]) == 120
text = json.dumps(rows, ensure_ascii=False)
assert json.loads(text) == rows
```

DictReader использует первую строку как имена полей. Значение cents равно строке "120". Преобразование к int выполняется отдельно.

## Типичная ошибка

JSON с правильным синтаксисом может иметь неправильную структуру. Данные {"cents":"сто"} не становятся числом после загрузки.
