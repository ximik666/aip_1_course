## Повторяющиеся подзадачи

Если один и тот же результат требуется многократно, его можно вычислить один раз и сохранить. Для числа способов подняться по лестнице шагами 1 или 2 последний шаг приходит либо с предыдущей, либо с предпредыдущей ступени. Эти варианты не пересекаются, поэтому ways[n]=ways[n-1]+ways[n-2].

## Состояние и база

Состояние должно содержать достаточно информации для продолжения решения. Здесь достаточно номера ступени. Для нулевой ступени существует один способ: не делать шагов, поэтому ways[0]=1. Для первой ступени способ тоже один. Неверная база меняет все последующие значения даже при правильном переходе.

## Порядок и память

Таблицу заполняем от меньших индексов к большим, чтобы зависимости были готовы. Если нужен только итог, достаточно двух предыдущих значений и O(1) ячеек вместо O(n). Эта оценка считает арифметическую операцию постоянной: фактическая стоимость больших целых растёт с числом разрядов. Сохранение всей таблицы полезно для объяснения и восстановления решения.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/30.py` из корня комплекта.

```python
def stair_ways(n):
    if type(n) is not int or n < 0:
        raise ValueError("нужно целое n >= 0")
    ways = [1] * (n + 1)
    for i in range(2, n + 1):
        ways[i] = ways[i-1] + ways[i-2]
    return ways[n]

assert stair_ways(0) == 1
assert stair_ways(5) == 8
```

Таблица для ступеней 0..5: 1,1,2,3,5,8. Каждый элемент использует только два уже вычисленных значения.

## Типичная ошибка

Динамическое программирование нельзя заменить жадным выбором без доказательства. Для монет 1,3,4 сумма 6 оптимальна как 3+3, а жадный выбор даёт 4+1+1.
