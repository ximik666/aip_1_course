## Протокол перебора

Итерируемый объект позволяет получить итератор. Итератор выдаёт следующий элемент через next и сообщает о завершении через StopIteration. Список можно обходить многократно, создавая новый итератор. Сам исчерпанный итератор обычно повторно данных не выдаёт. Это различие важно при повторных вычислениях.

## Приостановленное вычисление

Функция с yield возвращает генератор. При очередном запросе она выполняется до yield и сохраняет локальное состояние. Значения можно обрабатывать по одному без списка всех результатов. Но если потребитель вызвал list(generator), он сам материализовал все элементы и потерял преимущество по памяти.

## Функции как значения

Функцию можно передать другой функции, например key в sorted. Для простой операции подходит lambda, для сложной логики лучше именованная функция. Читаемость важнее минимального числа строк. Генераторное выражение внутри sum позволяет вычислить сумму преобразованных элементов без промежуточного списка.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/29.py` из корня комплекта.

```python
def squares(n):
    for i in range(n):
        yield i * i

g = squares(4)
assert next(g) == 0
assert list(g) == [1, 4, 9]
assert list(g) == []
assert sum(x*x for x in range(4)) == 14
```

Первый next потребляет 0. list получает только оставшиеся 1,4,9. Второй list работает с исчерпанным генератором.

## Типичная ошибка

Ленивость не гарантирует бесконечно малую память: генератор может удерживать большие объекты или файл до завершения.
