## Контракт задачи

Алгоритм задаёт однозначную последовательность действий. Начинаем с контракта: какие данные разрешены, какой результат требуется и что считать ошибкой. Для суммы покупок входом служат цены в целых копейках, выходом — неотрицательное целое число. Если цена отрицательна, это уже другая постановка: возврат товара или ошибка ввода. Программа не должна молча выбирать трактовку за автора задания.

## Исполнитель и состояние

Исполнитель выполняет команды, меняющие состояние. Состояние можно записать таблицей значений переменных после каждого шага. Сначала полезно решить пример вручную, затем записать псевдокод и только потом перевести его на Python. Это отделяет ошибку замысла от ошибки синтаксиса. Один успешный пример показывает возможность решения, но ещё не доказывает правильность для всех входов.

## Свойства решения

Для учебных задач требуем завершение на каждом допустимом входе и соответствие контракту. Конечность входа сама по себе не гарантирует завершение программы: цикл может не менять управляющую переменную. Проверяем обычный случай, минимальный вход и границу условия. Для алгоритма покупки упаковок отдельно рассматриваем точное деление и наличие остатка.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/01.py` из корня комплекта.

```python
n = 23
k = 6
packs = (n + k - 1) // k
print(packs)
assert packs == 4
```

Для 23 предметов и вместимости 6 три упаковки вмещают 18 предметов. Нужна четвёртая. При n=24 ответ также 4, при n=0 ответ 0. Предусловия: n — целое неотрицательное, k — целое положительное.

## Типичная ошибка

Округление обычного деления вниз теряет неполную упаковку. Нулевая вместимость недопустима.

## Совместная задача

База. По двум целым n≥0 и k>0 вывести число упаковок. Примеры: 0 6 → 0; 24 6 → 4; 25 6 → 5. Записать псевдокод и таблицу для последнего примера.

Сначала запишите вход и выход, решите пример вручную и выделите граничный случай. Только после этого переходите к реализации.
