## Проверка результата

Тест задаёт конкретный вход, ожидаемый результат и сравнение. Ожидаемый результат нужно получить независимо от проверяемой реализации. Если скопировать ту же ошибочную формулу в тест, оба вычисления согласуются. Хороший набор включает обычный случай, границы, пустой вход и запрещённые данные согласно контракту.

## Отладка по гипотезе

Сначала воспроизводим ошибку минимальным примером. Затем формулируем гипотезу и проверяем промежуточное состояние. Печать всех переменных без вопроса создаёт шум. После исправления добавляем регрессионный тест именно на найденный случай. Так ошибка становится постоянной частью защиты кода.

## Автоматический запуск

assert удобен в коротком учебном примере, но может отключаться оптимизированным запуском. Для итоговой проверки используем unittest с именованными тестами. Вещественные результаты сравниваем с допуском, если точное равенство не предусмотрено постановкой. Успешные тесты не являются математическим доказательством корректности на всех входах.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/14.py` из корня комплекта.

```python
import unittest

def average(a):
    return sum(a) / len(a) if a else None

class AverageTests(unittest.TestCase):
    def test_empty(self):
        self.assertIsNone(average([]))
    def test_values(self):
        self.assertAlmostEqual(average([1, 2]), 1.5)

assert average([1, 2]) == 1.5
```

Один тест проверяет договорённость о пустом входе, другой — арифметику. Они защищают разные ветви функции.

## Типичная ошибка

Отсутствие вывода у старого assert.py не всегда достаточно: важно проверить код завершения и убедиться, что проверки действительно запускались.
