## Уровни проверки

Модульный тест проверяет отдельную функцию, интеграционный — работу нескольких частей вместе. Пример интеграции: загрузить JSON, проверить схему, вычислить результат и сохранить отчёт. Успешные арифметические тесты не обнаружат неправильное имя поля при загрузке или неверную кодировку при записи.

## Свойства и эталоны

Для транспонирования проверяем T(T(A))=A, для сортировки — порядок и сохранение кратностей, для поиска пути — допустимость каждого ребра. Эти свойства дополняют конкретные ожидаемые ответы. Независимый эталон должен использовать иной способ решения или ручной пример, а не копию алгоритма.

## Воспроизводимый дефект

Отчёт об ошибке содержит минимальный вход, команду запуска, ожидаемое и фактическое поведение. Тестовые файлы создаём во временном каталоге. Случайные проверки фиксируют seed и сохраняют контрпример. В итоговом README указываем ограничения размеров и численной точности: это часть честного контракта проекта.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/31.py` из корня комплекта.

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory
with TemporaryDirectory() as folder:
    path = Path(folder) / "data.json"
    original = [{"name": "чай", "cents": 120}]
    path.write_text(json.dumps(original, ensure_ascii=False), encoding="utf-8")
    loaded = json.loads(path.read_text(encoding="utf-8"))
    assert loaded == original
    assert sum(r["cents"] for r in loaded) == 120
```

Проверка охватывает преобразование в JSON, запись, чтение и расчёт. Временный каталог удаляется после выхода из with.

## Типичная ошибка

Большое количество одинаковых тестов не заменяет покрытие разных контрактов. Нельзя объявлять проект корректным только по числу проверок.

Сначала запишите вход и выход, решите пример вручную и выделите граничный случай. Только после этого переходите к реализации.
