## Линейная проверка

Линейный поиск проверяет элементы по порядку и подходит для несортированных данных. Если требуется первый индекс, возвращаем результат сразу при первом совпадении. Отсутствие обозначаем -1. Худший случай требует n сравнений, дополнительная память постоянна.

## Половинное сужение

Бинарный поиск требует упорядоченности и отбрасывает половину оставшегося диапазона после сравнения со средним. В варианте lower_bound поддерживаем полуинтервал [lo,hi). Слева от lo находятся элементы меньше цели, начиная с hi — элементы не меньше цели. В конце lo==hi указывает позицию вставки.

## Стоимость подготовки

Поиск в готовом отсортированном списке занимает O(log n) сравнений. Если ради одного запроса сначала сортировать данные, нужно учитывать стоимость сортировки. Кроме того, индексы в отсортированном списке уже не совпадают с исходными. Контракт должен уточнять, какой индекс требуется.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/18.py` из корня комплекта.

```python
def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

assert lower_bound([1, 3, 3, 7], 3) == 1
assert lower_bound([], 3) == 0
```

Для [1,3,3,7] и цели 3 границы меняются (0,4), (0,2), (0,1), (1,1). Результат указывает первое возможное вхождение.

## Типичная ошибка

Возвращённая позиция может равняться len(a). Перед чтением a[pos] необходимо проверить границу.
