## Самоподобие задачи

Рекурсивная функция вызывает себя на меньшем экземпляре задачи. Для факториала n!=n*(n-1)!, а 0!=1. Базовый случай завершает цепочку. Кроме него нужно показать, что каждый допустимый вызов приближает аргумент к базе. Для отрицательного n обычное уменьшение на 1 делает обратное.

## Возврат результатов

Вызовы сохраняют локальные значения, пока дочерняя задача не завершится. Для factorial(3) сначала ждут вычисления factorial(2), затем factorial(1), затем factorial(0). После достижения базы результаты возвращаются вверх. Это потребляет дополнительную память на глубину рекурсии.

## Когда выбирать цикл

Простую линейную рекурсию часто удобнее заменить циклом. Python ограничивает глубину рекурсии, поэтому очень длинные цепочки не подходят для такой реализации. Рекурсия особенно наглядна для деревьев и разделения пополам. Она не делает алгоритм автоматически быстрым: наивные числа Фибоначчи многократно вычисляют одинаковые подзадачи.

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/24.py` из корня комплекта.

```python
def factorial(n):
    if type(n) is not int or n < 0:
        raise ValueError("нужно целое n >= 0")
    if n == 0:
        return 1
    return n * factorial(n - 1)

assert factorial(0) == 1
assert factorial(5) == 120
```

Для n=3 вызовы 3,2,1,0. Возвращаемые значения 1,1,2,6. Умножение происходит при возврате.

## Типичная ошибка

Увеличение предела рекурсии не исправляет отсутствие базы и может создать дополнительный риск переполнения стека.
