## Дизайн опыта

Сравниваем алгоритмы на одинаковых данных, иначе разница может объясняться входом. Фиксируем генератор случайных чисел, размеры и форму входов: случайный, возрастающий, убывающий, много повторов. Если алгоритм меняет список, каждый запуск получает свежую копию. Создание входа выполняется вне измеряемого участка.

## Что измеряется

perf_counter измеряет прошедшее время с подходящим для коротких интервалов разрешением. Для слишком коротких функций измеряем серию вызовов. Повторения позволяют увидеть разброс. Медиана меньше зависит от единичного фонового всплеска, но полезно сохранить и минимум, и максимум. Одно число без условий опыта мало говорит о качестве алгоритма.

## Ограничение эксперимента

Для квадратичных сортировок начинаем с 100,300,1000 элементов и увеличиваем только при приемлемом времени. Порог после завершённого запуска не способен прервать уже зависший вызов, поэтому безопасный план важнее поздней проверки. Не публикуем универсальное обещание «100000 элементов занимают столько-то минут».

## Пример с разбором

Перед запуском запишите ожидаемый результат или состояние. Затем выполните файл `examples/21.py` из корня комплекта.

```python
from random import Random
from time import perf_counter
from statistics import median
rng = Random(42)
base = [rng.randrange(1000) for _ in range(1000)]
times = []
for _ in range(5):
    sample = base.copy()
    start = perf_counter()
    result = sorted(sample)
    times.append(perf_counter() - start)
    assert result == sorted(base)
assert median(times) >= 0
```

Генерация и копирование находятся до start, проверка — после измерения. Встроенная sorted создаёт выходной список внутри измеряемой операции.

## Типичная ошибка

Сортировка одного и того же изменяемого списка в повторениях измеряет сначала случайный, а потом уже отсортированный вход.
