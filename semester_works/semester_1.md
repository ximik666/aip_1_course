# Семестровая работа 1 Комплексный калькулятор

## Назначение

Разработать модуль операций над комплексными числами и консольный интерфейс. Обязательное ядро реализуется самостоятельно без встроенного complex и внешних библиотек. В преподавательском эталонном тесте complex допустим как независимый способ проверки.

## Обязательный контракт

Модуль называется semestr_task.py. Функции summa(values), raznost(values), multi(values), divide(values) принимают ровно list длины 4: [a,b,c,d] для чисел a+bi и c+di. Элементы имеют точный тип int или float, bool и числовые строки запрещены. Значения конечны, модуль каждого не больше 10^6. Деление дополнительно требует c²+d²≥10^-12; меньший знаменатель считается выходом из учебной области допустимых данных. Это явное ограничение предотвращает непредсказуемый рост ошибки около нуля, а не математическое определение нулевого числа.

Возврат — новый list [real,imag] либо строка "error" при нарушении контракта. Вход не изменяется. Функции ничего не читают и не печатают. Внутри операций округления нет. Интерфейс может показывать две цифры после точки, но не меняет возвращённые значения.

| Операция | Формула результата |
|---|---|
| summa | [a+c,b+d] |
| raznost | [a-c,b-d] |
| multi | [ac-bd,ad+bc] |
| divide | [(ac+bd)/(c²+d²),(bc-ad)/(c²+d²)] |

Числовые ответы сравнивать через math.isclose с rel_tol=1e-9 и abs_tol=1e-9. Строку error сравнивать точно. Старые проверки с другим соглашением об округлении не являются нормативными для этой версии.

## Интерфейс

Пользователь выбирает add, sub, mul, div или quit. Затем вводит четыре компоненты через пробел. Неправильный ввод вызывает понятное сообщение и повтор, а не завершение с трассировкой. Обязательны обычный сценарий, обработка неизвестной команды и выход. Интерфейс вызывает функции ядра и не дублирует формулы.

## Приёмочные примеры

- summa([5,3,6,9]) → [11,12].
- raznost([1,2,3,4]) → [-2,-2].
- multi([1,2,3,4]) → [-5,10].
- divide([1,2,3,4]) → [0.44,0.08] с допуском.
- divide([1,2,0,0]) → error.
- summa([1,2,3]), summa([True,2,3,4]), summa(["1",2,3,4]), summa([NaN,0,0,0]) → error.
- Любая операция сохраняет исходный список.

## Индивидуальные варианты

1. История. Хранить последние 10 успешных операций, показывать по команде history, очищать по clear. Ошибки не попадают в историю. Проверить вытеснение самой старой записи.
2. Пакетный JSON. Читать список объектов {op,values}, для каждого возвращать {index,result}. Ошибка одной записи не останавливает остальные. Проверить пустой список и неизвестную операцию.
3. Цепочка операций. Начинать с одного комплексного числа, затем последовательно применять команды с очередным операндом. При ошибке аккумулятор не меняется. Проверить два успешных шага и нулевой делитель между ними.
4. Полярное представление. Дополнительно вычислять модуль hypot(a,b) и аргумент atan2(b,a) в радианах. Для нулевого числа аргумент возвращать None. Проверить четыре квадранта.
5. Журнал CSV. Записывать время, операцию, компоненты и результат успешной операции. При чтении восстанавливать число записей и суммарное количество каждой операции. Проверить русское имя файла и повторный запуск без потери истории.
6. Проверка тождеств. Создать детерминированный генератор 30 пар малых чисел и отчёт о коммутативности суммы и произведения, z+0=z, z*1=z, (z/w)*w≈z для разрешённого w. Отчёт показывает конкретный контрпример при провале, а не только False.
